# Tag Studio — SEO Page Builder

## 0. متى تستخدم المهارة دي
- إنشاء أو تحديث أي صفحة تحت `/services`, `/locations`, `/tools`, `/work`, أو مقال Pillar/Supporting في المدونة.
- بناء "منظومة" (Topic Cluster) كاملة: صفحة مركزية + دليل داعم + دليل تكلفة.
- الرد على أسئلة تشخيصية من خبير SEO أو العميل عن حالة الموقع.
- تشخيص فجوة الفهرسة (صفحات منشورة ≠ صفحات مفهرسة).

## 1. حقائق الموقع الثابتة (تحقق منها، لا تفترضها)
| البند | القيمة المعروفة | طريقة التحقق الإلزامية |
|---|---|---|
| الإطار | Next.js App Router + React + TS + Tailwind | `package.json` → اقرأ رقم إصدار `next` فعلياً (14.2.25) |
| الاستضافة | Vercel | `vercel.json` أو إعدادات المشروع |
| اللغة | عربي فقط، `lang="ar" dir="rtl"` | `app/layout.tsx` |
| التموضع | B2B عام بقطاعات فرعية (طبي، مطاعم، تعليمي، شركات/مقاولات) | مثبت ومؤكد رسمياً |
| ملفات القواعد | `Documents/.agents/AGENTS.md` = قواعد مقالات القطاع الطبي فقط، مش تعريف البراند | لا تعمم قواعده على باقي القطاعات |
| آلية التتبع | GA4 gtag.js مباشر (`G-7EET2GCC8N`) عبر `dataLayer` | ابحث في `app/layout.tsx` والمكونات |
| الملفات الحاكمة | `app/robots.ts`, `app/sitemap.ts`, `app/layout.tsx`, `lib/servicesData.ts`, `lib/blogData.ts`, `package.json` | تُقرأ كاملة في المرحلة 0 |
| السايت ماب | `app/sitemap.ts` (ديناميكية) | اقرأ الملف كاملاً، تأكد إن الصفحة الجديدة هتدخل تلقائياً |
| robots.txt | `app/robots.ts` | يسمح للجميع ويشير للسايت ماب |
| CTA الرئيسي | زر واتساب | تأكد من وجود حدث تتبع `whatsapp_click` عبر `gtag` (حالياً مفقود ويحتاج إضافة) |
| الأقسام والخدمات | 15 slug خدمة + صفحة هب واحدة = 16 مسار خدمات إجمالي (تصحيحاً لذكر 16 كـ slugs سابقاً) | أعد العد في كل جلسة من ملفات الداتا والمسارات |

## 2. بروتوكول المصداقية (غير قابل للتفاوض)

### 2.1 وسوم المعلومة
كل معلومة في أي رد لازم تتوسم بواحدة من دي:
- **[بيانات]** — من ملف قرأته أو أمر نفذته **وعرضت ناتجه في الرد**.
- **[محتاج منك]** — بيانات لا تملك وصولاً لها (GSC, GA, PSI, CrUX). اكتب بالظبط إيه المطلوب وإزاي يتطلع.
- **[استنتاج]** — تحليلك أنت، مع ذكر الأساس.

### 2.2 ممنوعات مطلقة
- ❌ ذكر أي رقم PageSpeed/Lighthouse/CrUX لم تشغّله في نفس الجلسة أو لم يعطه المستخدم.
- ❌ وصف مصادر الترافيك أو الكلمات المفتاحية من غير إكسبورت GSC فعلي.
- ❌ صفات تسويقية في الردود التقنية: "فائق"، "أعلى المعايير"، "عالمي"، "الأفضل".
- ❌ قراءة جزء من ملف (60 سطر) ثم ادعاء الإلمام به. الملفات الحاكمة تُقرأ **كاملة**.
- ❌ تنفيذ أمر وعدم عرض ناتجه. لو الناتج طويل، اعرض ملخص + أول 20 سطر.
- ❌ اقتراح إنشاء صفحة قبل التأكد إنها مش موجودة عبر الجرد المزدوج (§3 Gate 0).
- ❌ الخلط بين "عدد الصفحات في السايت ماب" و"عدد الصفحات المفهرسة في جوجل".

### 2.3 قاعدة الجواب الناقص
"معنديش الرقم ده دلوقتي، وده اللي محتاجه عشان أطلعه" أقوى من رقم لامع قابل للتكذيب. طبّقها دايماً.

## 3. المنهجية: 5 مراحل ببوابات موافقة

### المرحلة 0 — الجرد (Inventory)
**المخرجات الإلزامية قبل أي اقتراح:**
1. **جرد مزدوج إلزامي** (المجلدات لوحدها مضللة مع Dynamic Routes):
   - أ) `Get-ChildItem app/<section> -Recurse -Filter page.tsx`
   - ب) لو ظهر مجلد `[slug]` أو `[id]`: اقرأ كل الـ slugs من ملف الداتا المقابل (`lib/servicesData.ts` أو `lib/blogData.ts`).
   - ج) اعرض الناتجين. الصفحة تعتبر "موجودة" لو ظهرت في أي منهما.
2. جدول: URL الموجود / الموضوع / المصطلح اللي بيستهدفه / درجة التداخل مع الصفحة المقترحة (لا/جزئي/كامل).
3. مذكرة تقنية: إصدار Next، آلية السايت ماب، `app/robots.ts`، Schema الموجودة عالمياً في layout، هل تتبع الواتساب شغال.
4. **[محتاج منك]** Baseline من GSC آخر 90 يوم: ظهور/نقرات/متوسط ترتيب للاستعلامات ذات الصلة + Coverage report.

**Gate 0 — قرار أحد أربعة:**
- لا توجد صفحة → أنشئ.
- صفحة موجودة وضعيفة → حدّث في مكانها (احتفظ بالـ URL).
- صفحتان متداخلتان → ادمج + 301.
- الصفحة موجودة وقوية → لا تنشئ، اعمل Supporting content بس.

### المرحلة 1 — الاستهداف (Targeting)
1. **3 مرشحات على الأقل** للمصطلح الرئيسي.
2. لكل مرشح: نية البحث + نوع النتائج في SERP المستهدف + ميزات SERP.
3. **[محتاج منك]** لو الموقع بيظهر أصلاً على أي مرشح في GSC.
4. قرار: مصطلح رئيسي واحد (H1 + URL + Title) + 2-3 ثانوية (H2s) + قائمة أسئلة PAA حقيقية للـ FAQ.
5. **خريطة منع الأكل الذاتي (Cannibalization Map).**

**Gate 1:** موافقة المستخدم على المصطلح وتوزيع الاستهداف.

### المرحلة 2 — الهيكل والروابط (Outline & Links)
1. Outline الصفحة المركزية بالـ 9 أقسام (§4).
2. Outline للدليل الداعم ودليل التكلفة.
3. **مصفوفة الروابط الداخلية** (§5).
4. **Checklist دراسة الحالة** (§6).

**Gate 2:** موافقة المستخدم على Outline والمصفوفة. **ممنوع كتابة حرف من النص قبل الـ Gate دي.**

### المرحلة 3 — الكتابة والبناء
- اكتب النص بقواعد §7.
- نفّذ الطبقة التقنية §8 **في نفس التسليم**.
- الترتيب: الصفحة المركزية أولاً → تُنشر → الدليل الداعم → دليل التكلفة.

### المرحلة 4 — المراجعة والقياس
- نفّذ Checklist §10 قبل الـ merge.
- بعد النشر: طلب فهرسة من GSC للصفحات الجديدة.
- سجّل موعدي مراجعة **30 و90 يوم** بمقارنة صريحة بالـ Baseline.

## 5. مصفوفة الروابط الداخلية (Closed Loop)
```
الرئيسية / هب الخدمات ──► الصفحة المركزية
الصفحة المركزية ◄──► الدليل الداعم
الصفحة المركزية ◄──► دليل التكلفة
الدليل الداعم ◄──► دليل التكلفة
3-5 صفحات قديمة ذات صلة (blog/work/tools) ──► الصفحة المركزية
```

## 6. Checklist دراسة الحالة (Proof)
لا تُنشر دراسة حالة بالاسم إلا لو كل البنود ✅:
- [ ] إذن العميل بذكر الاسم والشعار (مكتوب).
- [ ] الأرقام (قبل/بعد) موثقة بمصدر يمكن إبرازه لو طُلب.
- [ ] صور بجودة نشر وحقوقها لتاج ستوديو.
- [ ] لا تصريح بنتائج تعاقدية للعميل بدون تأكيد منه.
لو أي بند ❌ → اعرضها مجهّلة ("عميل في قطاع الإسكان المؤسسي") أو أجّلها.

## 7. قواعد النص
- **الجمهور:** صناع القرار (مدير تسويق / مشتريات / مالك شركة). لغة عربية مؤسسية، جمل قصيرة، لا حشو.
- **الطول حسب النوع:**
  - صفحة خدمة (Pillar): 1,500-2,500 كلمة — تحويل وهيكل تجاري، مش موسوعة.
  - دليل داعم / مقال Topical: 2,500-3,500 كلمة — تغطية شاملة.
  - دليل تكلفة: 1,200-2,000 كلمة.
  - صفحة مدينة: 800+ كلمة محتوى محلي فعلي، وإلا لا تُنشأ.
- **الادعاءات التنظيمية:** صيغة "عادةً تطلب الجهات…"، "من الشائع أن تشترط لجان التأهيل…". ممنوع صياغتها كنص قانوني قطعي.
- **الأسعار:** عوامل لا أرقام في صفحة الخدمة. نطاقات واسعة فقط في دليل التكلفة.
- **الـ FAQ:** أسئلة حقيقية (PAA + واتساب)، إجابة 40-80 كلمة، تصلح كـ FAQPage schema.

## 8. الطبقة التقنية (في نفس الـ PR)
```
[ ] Title ≤ 60 حرف عربي، فيه المصطلح الرئيسي أولاً
[ ] Description ≤ 155 حرف، فيها المصطلح + فائدة + النطاق الجغرافي
[ ] canonical صريح بالنطاق الكامل https://www.wearetagstudio.com/...
[ ] OG image مخصصة 1200×630 + og:locale ar_SA
[ ] Schema JSON-LD: Service (أو Article للأدلة) + FAQPage + BreadcrumbList
    (Organization مرة واحدة في layout فقط، لا تكررها)
[ ] الصفحة ظاهرة في app/sitemap.ts (تحقق بفتح /sitemap.xml بعد البناء)
[ ] app/robots.ts: يسمح بالزحف للمسار الجديد + رابط السايت ماب فيه صحيح بالنطاق الكامل
[ ] مضافة للـ Navigation أو هب /services
[ ] كل صورة: alt وصفي، WebP/AVIF، next/image بأبعاد صريحة
[ ] زر واتساب: رسالة مسبقة فيها اسم الخدمة + حدث whatsapp_click يُرسل عبر
    gtag('event', 'whatsapp_click', { page_path: '...', service_name: '...' })
[ ] لا noindex بالخطأ (افحص metadata.robots في page و layout)
[ ] الصفحة تبنى بدون أخطاء: npm run build
```

## 9. أوامر التشخيص الجاهزة (PowerShell / Windows)
```powershell
# جرد مجلدات الصفحات
Get-ChildItem -Path "app/services" -Directory

# جرد الـ slugs الحقيقية من ملف البيانات المصدري
Select-String -Path "lib/servicesData.ts" -Pattern 'slug:\s*["'']([^"'']+)["'']' | ForEach-Object { $_.Matches.Groups[1].Value }

# فحص app/robots.ts
Get-Content "app/robots.ts"

# اكتشاف آلية التتبع
Get-ChildItem -Path "app","components" -Recurse -Filter "*.tsx" | Select-String -Pattern "dataLayer|gtag|GTM-|fbq|posthog"

# البحث عن noindex في المشروع كله
Get-ChildItem -Path "app" -Recurse -Filter "*.tsx" | Select-String -Pattern "noindex|index:\s*false"

# التحقق من بناء المشروع
npm run build
```

## 10. Checklist المراجعة قبل النشر
- مطابقة الـ Outline المعتمد في Gate 2.
- تنفيذ مصفوفة الروابط في الاتجاهين.
- فحص Schema عبر Rich Results Test.
- تجربة زر الواتساب والتأكد من تسجيل الحدث.
- تسجيل تاريخ النشر والـ Baseline.

## 11. تشخيص فجوة الفهرسة
1. **[محتاج منك]** GSC → Pages (Coverage): Indexed / Crawled-not-indexed / Discovered-not-indexed.
2. **[بيانات]** `robots.txt` سليم؟ السايت ماب مسجلة ومقبولة؟
3. **[بيانات]** فحص noindex و canonicals في كل المسارات.
4. **[محتاج منك]** عمر الدومين وتاريخ نشر المحتوى.
5. **[استنتاج]** لو الأغلب Crawled, currently not indexed = مشكلة جودة/تكرار وليست مشكلة تقنية.

## 12. قالب الرد على خبير SEO
```
1. site: وقف عند [رقم شفته بنفسك]. السايت ماب فيها [رقم من الأمر] URL. Coverage مرفق. عمر الدومين [X].
2. PSI موبايل [تاريخ اليوم]: [رابط]. Perf [ ] LCP [ ] INP [ ] CLS [ ]. (أو: "لسه مشغلتوش، هبعته خلال ساعة")
3. Next.js [إصدار من package.json] App Router + Tailwind على Vercel. كود مخصص.
4. عربي فقط. لا hreflang. canonical على كل صفحة.
5. GSC آخر 90 يوم: إكسبورت Queries + Pages مرفق. (أو: "هطلعه بكرة")
6. /services هب + [عدد فعلي] صفحة فرعية، القائمة: [...]
```

## 14. الخبايا (Gotchas) المجمّعة
1. ناتج الأوامر اللي مبيظهرش في الرد = كأنه ما اتنفذش. اعرضه دايماً.
2. قراءة 60 سطر من ملف ≠ قراءة الملف.
3. "230 صفحة في السايت ماب" مش إجابة على "كام صفحة في site:".
4. أرقام PageSpeed من الذاكرة = كذب مؤجل. الخبير هيشغّله بنفسه.
5. وصف الترافيك من غير GSC = تخمين. سمّيه تخمين أو ما تكتبوش.
6. قبل "أنشئ صفحة" لازم Gate 0. الجرد بالمجلدات لوحدها مع `[slug]` مضلل.
7. Organization schema مرة واحدة في layout؛ تكرارها في كل صفحة خطأ.
8. صفحات المدن اللي بتكرر نص الخدمة بتضر — محتوى محلي فعلي أو لا شيء.
9. الرسالة المسبقة في زر واتساب لازم فيها اسم الصفحة، مع إرسال حدث `whatsapp_click`.
10. بعد النشر: تغيير الـ URL بدون 301 بيضيع كل اللي اتعمل.
11. لا تفصل قسم القطاع لصفحة مستقلة قبل 90 يوم بيانات تثبت الطلب.
12. الـ Baseline يتسجل قبل النشر، مش بعده.
13. المستخدم بيسأل "إيه رأيك" = عايز تقييم صريح بنقاط ضعف، مش موافقة.
14. أي Gate اتخطيتها من غير موافقة صريحة → ارجع لها.
15. مجلد `[slug]` واحد ممكن يخفي 15 صفحة. الجرد بالملفات المصدرية (`servicesData.ts`) إلزامي.
16. لما تقتبس من "ملف قواعد" أو "محادثة سابقة": اذكر المسار الكامل واعرض النص، أو اعتبرها [استنتاج].
17. تقييمك للمهارة أو للخطة يخضع لنفس بروتوكول §2 — النقد من غير وسوم = نفس الهلوسة بشكل مهذب.
18. "نبدأ مباشرة في التطبيق" ممنوعة كخاتمة. الخاتمة الوحيدة المقبولة: "أبدأ المرحلة 0 وأقف عند Gate 0".
19. عدد الصفحات الحية = ناتج npm run build (Generating static pages X/X) مش عدد الـ slugs في ملفات الداتا. المحتوى المجدول مخزون مش صفحات حية.
20. قبل أي قرار عن الفهرسة: اقرأ فلترة التاريخ في page.tsx و sitemap.ts للقسم.
21. أي مقال متولّد برمجياً: افحص تطابق العنوان/الـ slug قبل النشر. bug في مقالين = فحص إلزامي للكل.
22. "في السايت ماب" ≠ "مفهرسة" ≠ "بتظهر". تلات أرقام مختلفة تماماً، سمّي كل واحد باسمه الصريح.
23. أي حسبة تعرضها: اكتب المعادلة الرياضية الصريحة.
24. نتائج أداة البحث تتعرض خام بروابطها ومصادرها، مش بإعادة صياغة إنشائية.
25. لا تقترح تقديم تاريخ نشر محتوى مجدول كطريقة لتخطي Gate.
26. المهارة للعملية العامة (Process)، وحقائق المشروع في docs/seo-tracker.md — لا تخلط بينهما.
